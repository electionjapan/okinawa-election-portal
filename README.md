# 沖縄選挙ポータル v0.9.13 — GitHubアップロード用

このフォルダは Streamlit Community Cloud 用の最小構成です。

## 更新方法
1. このフォルダの中身をすべて選択
2. GitHub の `electionjapan/okinawa-election-portal` で **Add file → Upload files**
3. 同名ファイルは上書きされます
4. Commit changes
5. Streamlit Community Cloud の再読み込みを待つ

## 反映確認
トップページ上部に **v0.9.13 · NEW MAP** と出れば新版です。
開票速報・過去の選挙結果にも **v0.9.13 · NEW MAP · 模式配置** と表示されます。

## 地図について
アプリが読む表示用地図は `data/map_layout_v0912.geojson` だけです。
旧レイアウトGeoJSON(v0910以前)はこの配布物に含めていません。
ファイル名にバージョンを付けているのは、Streamlit Community Cloud側やブラウザ側の
キャッシュが古い地図を出し続けるのを防ぐためです。`st.cache_data` はv0.9.10で読込・整形処理に
再度付与しています(操作のたびにJSONを読み直さないようにするための高速化目的で、地図データ
自体はファイル名を変えるたびに必ず再取得されるため、古いキャッシュが表示され続ける心配はありません)。

## v0.9.12
- 市町村別一覧を「リード票」で並び替えたとき、候補者がバラバラに混ざる問題を修正。1位候補ごとにグループ化してから、そのグループ内でリード票の大きい順に並べるようにした(例: A候補が優位な市町村を票差の大きい順にまとめ、続けてB候補が優位な市町村をまとめて表示)。なお表の列見出しをタップして並び替えた場合は、Streamlit標準の単純な数値ソートに戻る点に注意。
- 石垣市を「八重山」グループから独立させ、模式地図の宮古と八重山の間に単独の枠として配置。八重山の枠には竹富町・与那国町のみが残る形に変更。
- 2本指ピンチズームについて再検討。`touch-action: none`に変更してもなお動作しないとの報告を受け、原因をタッチジェスチャーの検出そのものではなく、この地図が自前描画のポリゴン(Scatter)であり、Plotly.js側にピンチ距離からズーム量を計算する実装が無い(または非常に不安定)という、より根本的な制約と判断。指のジェスチャーでの解決を諦め、グラフ右上に常時表示されるズームボタン(＋／－)をタップして拡大・縮小できるよう変更。ボタン自体もモバイルでタップしやすいよう大きめに表示。地図の説明文もこの操作方法に合わせて修正。


## v0.9.11
- 2本指ピンチズームが効かない問題への対応(1回目)。前版で指定した`touch-action: pan-y pinch-zoom`は「ブラウザ自身にピンチ処理を任せる」指定だったが、Streamlitアプリ側でブラウザ標準のピンチズームが無効化されているため、そもそも何も起きていなかった。`touch-action: none`に変更し、タッチ操作の処理をPlotly側のJavaScriptに渡すよう修正したが、この変更だけでは解決しなかった(v0.9.12参照)。


## v0.9.10
- トップへ戻るボタンがStreamlit標準ヘッダーの裏に隠れる問題を修正。標準ヘッダー自体を非表示にし、戻るボタン行を画面上部に固定表示(sticky)。
- 石垣市・与那国町の模式地図サイズを補正。与那国島が過大表示、石垣島が過小表示だったため、石垣島本体をさらに1.22倍拡大、与那国島本体を0.27倍に縮小し、実際の面積比に近い見た目へ調整。
- 地図をスマホで指ピンチ操作した際にズームできるよう、Plotlyチャートに`touch-action`のCSSを指定(※この時点の指定は不十分で、v0.9.11でも未解決。最終的にv0.9.12でズームボタン方式に変更)。
- 軽量化: 地図データの座標点数を30,670点→6,006点(約80%減)に削減。海面下の岩礁・干潟など目に見えない微小ポリゴンを間引き、残った海岸線もDouglas-Peucker法で簡略化。ファイルサイズは1.22MB→0.25MBに縮小。
- データ読込処理に`st.cache_data`を再付与し、スライダー操作などの再実行を高速化。
- 開票速報のシミュレーション方式は現状維持(本番の実入力機能への切替は別途対応予定)。
